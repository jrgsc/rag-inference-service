# RAG Inference Service

Portfolio project: a Node.js API gateway in front of a Python FastAPI service that does retrieval-augmented generation (RAG) over a small corpus, using the Claude API.

## Structure

- `node-gateway/` — Express gateway (auth, rate limiting, caching, routes requests to the Python service)
- `python-service/` — FastAPI service (embeddings, retrieval, Claude calls)
- `docker-compose.yml` — spins up both services locally

## Status

RAG pipeline (chunk → embed → retrieve → answer) is done. Gateway now proxies
`/query` to the Python service with API key auth, rate limiting, and Redis
response caching.

## Corpus

The RAG corpus isn't included in this repo (it's personal/work docs, gitignored
under `python-service/corpus/`). To run this end-to-end yourself, drop your own
markdown docs in there and point the service at them (`CORPUS_DIR` env var).

Embeddings are generated with [Voyage AI](https://www.voyageai.com/), retrieval
runs through a local [Chroma](https://www.trychroma.com/) index, and answers
are generated by Claude.

## Local dev

```
cp .env.example .env
# fill in ANTHROPIC_API_KEY, VOYAGE_API_KEY, and GATEWAY_API_KEY (any random string)
docker compose up --build
```

Build the index once (from inside the python-service container or a local venv):

```
python -m app.ingest
```

Then query through the gateway (this is the intended entry point, not the Python service directly):

```
curl -X POST http://localhost:3000/query \
  -H "Content-Type: application/json" \
  -H "x-api-key: <your GATEWAY_API_KEY>" \
  -d "{\"question\": \"...\"}"
```

Rate limit is 20 requests/min per gateway instance. Identical questions are cached in Redis for an hour.

Gateway health check: http://localhost:3000/health
Python service health check: http://localhost:8000/health
